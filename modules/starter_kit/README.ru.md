# Starter Kit

[English](README.md) | **Русский**

**Версия модуля: 0.1.2 (в разработке).**

Необязательный модуль MajorDoMo, который устанавливает демонстрационные наборы
в свежую систему.

## Принципы

- Никаких изменений ядра и схемы БД.
- Языковые файлы модуля лежат в `lang/`; словари ядра не меняются.
- Создаются только штатные сущности MajorDoMo: классы, свойства, объекты,
  методы, скрипты, сцены, макеты и текстовые файлы.
- Ничего не ставится автоматически: администратор выбирает наборы на странице
  модуля (`admin.php?action=starter_kit`).
- Удаляется только созданное модулем и не изменённое пользователем.
- Без внешних API, MQTT, Telegram и реального железа.

## Язык

Модуль использует свои словари в `modules/starter_kit/lang/` (`default.php`,
`ru.php`). Словари ядра `languages/*.php` не изменяются; отсутствующие ключи
подставляются из английского.

## Состояние установки

Список созданных сущностей хранится в `project_modules.DATA` модуля
`starter_kit` (сериализованный массив, ключ `installed`). Для каждой сущности
хранится ID и хеш сгенерированного кода, поэтому удаление и обновление замечают
ручные правки. Там же хранится версия установленного набора.

## Формат пакета

Пакет — PHP-файл в `packages/`, возвращающий массив:

```php
return array(
    'id' => 'example',
    'version' => 1,
    'title_key' => 'LANG_KEY_TITLE',
    'description_key' => 'LANG_KEY_DESCRIPTION',
    'requires' => array('basic_entities'),   // необязательно: уже установленные наборы
    'hints' => array(                        // необязательно: подсказки на странице модуля
        'shows' => 'LANG_KEY_SHOWS',
        'adapt' => 'LANG_KEY_ADAPT'
    ),
    'texts' => array(                        // необязательно: {{TOKEN}} => LANG_KEY
        'ON' => 'STARTER_KIT_TEXT_ON'
    ),
    'classes' => array(
        array(
            'title' => 'SK_Example',
            'parent' => 'Timer',       // необязательно; нужно для onNewMinute/onNewHour/onNewDay
            'description' => '...',
            'template' => '<b>%.object_title%</b>: %.status%', // classes.TEMPLATE
            'properties' => array(
                'foo' => array(
                    'keep_history' => 0,
                    'onchange' => 'onFooChanged', // необязательный onchange-хук
                    'description' => '...'
                )
            ),
            'methods' => array('bar' => '/* PHP-код без <?php */')
        )
    ),
    'objects' => array(
        array(
            'title' => 'StarterExample',
            'class' => 'SK_Example',
            'description' => '...',
            'properties' => array('foo' => 'значение по умолчанию'),
            'methods' => array('onNewMinute' => '...')
        )
    ),
    'text_files' => array(
        array('name' => 'starter_kit_example', 'content' => '...')
    ),
    'scripts' => array(
        array('title' => 'SK_ExampleScript', 'description' => '...', 'code' => '...')
    ),
    'scenes' => array(
        array(
            'title' => 'SK Example scene',
            'priority' => 10,
            'elements' => array(
                array(
                    'title' => 'Run example',
                    'type' => 'button',
                    'top' => 100, 'left' => 100, 'width' => 260, 'height' => 60,
                    'action_object' => 'StarterExample',
                    'action_method' => 'bar'
                )
            )
        )
    ),
    'layouts' => array(
        array(
            'title' => 'SK Example page',
            'type' => 'html',
            'priority' => 50,
            'code' => '<div>%StarterExample.status|10%</div>'
        )
    )
);
```

Порядок создания: классы, объекты, текстовые файлы, скрипты, сцены, макеты.
Родительские классы указывайте до наследников.

`requires` перечисляет наборы, которые должны быть установлены раньше; установка
и обновление с отсутствующими зависимостями отклоняются, а страница модуля
показывает их. При выборе нескольких наборов установка идёт в порядке
зависимостей, удаление — в обратном.

`{{TOKEN}}` заменяются при установке по карте `texts` (`TOKEN => LANG_KEY`),
поэтому заголовки, описания, шаблоны и код попадают в систему на текущем языке.
В текстах нельзя использовать одинарные кавычки: код методов — это
однокавычковый PHP.

Хуки `onNewMinute`, `onNewHour`, `onNewDay` вызывает `scripts/cycle_main.php`
для объектов класса `Timer` и его наследников.

Кнопки сцен (`type=button`) вызывают `action_object.action_method`
(`ACTION_OBJECT` / `ACTION_METHOD` модуля `scenes`).

`layouts` создаёт страницу фронтенда (`TYPE=html`) и её файл
`cms/layouts/<ID>.html`; страница появляется вкладкой на главной. В коде можно
использовать штатные `%Object.Property|секунды%`. При удалении файл удаляется
вместе со строкой.

`text_files` создают `cms/texts/<name>.txt`, видны в
**Панель управления → Текстовые файлы** и читаются скриптами через `LoadFile()`.

`classes[].template` записывается в штатное поле `classes.TEMPLATE` и использует
обычные `%.property%` (`%.object_title%` подставляется автоматически).

## Версии и обновления

Версия пакета — целое число. Страница модуля показывает доступную версию и
метку обновления, если установленная меньше. Кнопка **«Обновить выбранные»**
запускает аддитивное обновление:

1. создаются новые классы, объекты, текстовые файлы, скрипты, сцены и макеты;
2. классам и объектам этого модуля добавляются недостающие свойства и методы;
3. скрипты, макеты и текстовые файлы обновляются, только если их содержимое
   совпадает с сохранённым хешем;
4. существующие сцены не перезаписываются.

Изменённые пользователем сущности пропускаются с сообщением. Полный сброс —
удалить набор и установить заново.

## Правила безопасности

1. Установка прерывается до создания сущностей, если сущность с таким именем уже
   есть.
2. Повторная установка установленного набора — no-op.
3. Удаление пропускает переименованные, дополненные свойствами/методами или
   изменённые сущности.
4. Классы, у которых есть объекты или наследники, не удаляются.
5. Сцены удаляются, только если совпадают названия, набор элементов, подписи
   кнопок и действия.
6. Страницы удаляются, только если не изменены строка `layouts` и файл
   `cms/layouts/<ID>.html`.
7. Текстовые файлы удаляются, только если их содержимое не изменено.
8. Набор нельзя удалить, пока от него зависит другой установленный набор;
   сначала удалите зависимые.
9. Удаление модуля из списка модулей убирает только запись реестра; наборы
   удаляйте явно со страницы модуля.

## Текущие наборы

- `clock_chime` v1 — `SK_Clock` / `StarterClock`: время, тихие часы, счётчик
  ударов, опциональный `say()`.
- `sun_times` v1 — `SK_Sun` / `StarterSun` + `SK_SunTimes`: рассвет, закат,
  гражданские/навигационные/астрономические сумерки и `dayPart` через
  `date_sun_info()`.
- `basic_entities` v1 — `SK_Device` и наследники `SK_Lamp` / `SK_Sensor` /
  `SK_Button` / `SK_Thermostat`, `SK_Room`, шаблоны классов, демо-объекты и
  `SK_EntitiesDemo`.
- `modes` v1 — три объекта `OperationalModes` (Debug, Гости, Отпуск), хаб
  `SK_Modes` / `StarterModes` и скрипты переключения; требует
  `basic_entities`.
- `scenes` v2 — шесть сцен (Доброе утро, Доброй ночи, Ушли, Пришли, Кино,
  Гости) на `SK_Scene` / `StarterScenes`; требует `basic_entities` и `modes`.
- `scripts` v2 — приветствие, офлайн-проверка, имитация присутствия,
  расписание на два слота и отчёт в текстовый файл (`SK_Scripts`,
  `SK_Presence`, `SK_Schedule`); требует `basic_entities` и `modes`.
- `hints` v1 — `starter_kit_hints.txt`, `SK_Hints` / `StarterHints` и
  `SK_ShowHints`; требует `basic_entities`.
- `panel` v2 — вкладка фронтенда с живыми карточками лампы, датчика,
  термостата, комнаты, режимов, сцен, скриптов и подсказок; требует
  `basic_entities`, `modes`, `scenes`, `scripts` и `hints`.

`SK_Presence` и `SK_Schedule` — наследники `Timer`, поэтому их
`onNewMinute` / `onNewDay` начнут вызываться после перезапуска `cycle_main`
(модуль циклы при установке не перезапускает).

## Тесты

```sh
php tests/package_validate.php
php tests/installer_smoke.php
```

Валидатору нужен только PHP CLI: он проверяет формат пакетов, синтаксис методов
и скриптов, цели `onchange`, родительские классы, подстановки `{{TOKEN}}`,
зависимости, подсказки, действия сцен, ссылки в макетах и имена текстовых файлов.

Smoke-тест подменяет SQL и `ROOT` и проверяет создание/безопасное удаление сцен,
макетов и текстовых файлов, а также аддитивные обновления пакетов (неизменённое
обновляется или удаляется, изменённое остаётся). Реальную схему БД он не
проверяет: перед релизом нужен полный прогон на стенде.
